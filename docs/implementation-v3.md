## 변경된 동작

- 축구의 유럽 5대리그/K리그/아시안게임 허용 목록을 없앴다. 공식 경기표에서 조회된 **모든 축구 리그**를 표시한다. 기존 제외 시장(SUM·승1패·승5패·전반 승패·전반 언오버)은 유지한다.
- 실제 경기 ID는 종목·리그 식별자·홈/원정 식별자·UTC 시작시각으로 분리했다. 회차와 판매번호는 offer에 남긴다. 같은 실제 경기의 여러 회차는 하나의 카드에 표시한다. 다른 시작시각의 더블헤더는 합치지 않는다.
- 과거 패턴 탐색은 유지하되, 작은 표본의 전승은 `과거 n건 중 n건`으로 표시한다. 팀→리그→종목 고정 신뢰도, 중첩 사례 일치 수 가점, A등급 추천을 제거했다. 과거 적중률은 `live-core`, 모델 확률은 별도 `prediction-core`/`model-engine`에서 처리한다.
- 고신뢰는 별도 탭이다. 시작시간순/KST이며, 발매 종료 후에도 시작 전이면 관찰용 배지를 붙여 기본 포함한다. 모델 미승인 시 정식 빈 상태를 제공한다. 고정 70%·배당 1.40 조건과 사용자 확률·배당 필터를 제거했다. 날짜·리그·시장 필터는 경기별 최고 후보를 고른 뒤 화면만 좁힌다.
- 같은 실제 경기의 시장을 여러 추천으로 세지 않는다. 각 시장에서 확률이 가장 큰 결과 하나를 고르고, 다시 경기 전체에서 가장 높은 후보 하나만 남긴다. 동률은 결과 배열의 첫 슬롯과 고정된 시장 식별자 순서로 결정한다.
- 상세에서 전체 결과별 시장 기준확률과 모델 확률, 정산·확률 의미, 각 시각, 모델/정책 버전, 원장 링크를 확인한다. 과거 Wilson 구간을 개별 경기 예측구간으로 사용하지 않는다.
- 검증 탭은 축구 M0/M1/M2의 실제 2026 Log loss·Brier·확률구간을 표시한다. 모델의 독립시험과 고신뢰 분류의 후향 재현을 분리한다. 두 등급의 2025 경계·표본·적중률과 2026 재현 표본·구간을 함께 표시하며 관측·보류 기록과 결과 수정 이력은 삭제하지 않는다.
- 초기배당 조회는 `openingLine`을 사용한다. 결측 기준점을 0으로 바꾸지 않고, CSV의 0점과 실제 배당 변경횟수를 보존한다. 축구 시트 NPB 4행은 원본을 남겨 두고 탐색 모수에서 격리한다.
- 새로고침과 경기 상세 왕복의 기존 스크롤 복원 구조를 유지했다.

### 원천 매핑

- 공식 배당: 기존 Betman 공개 HTTP 조회의 `inqCacheBuyAbleGameInfoList.do`, `schedule.do`, `gameInfoInq.do`. 다른 사이트/해외 배당 대체 경로 없음.
- `gameDate`/`endDate`: 원본 UTC epoch ms → 절대시각 보존. 표시만 Asia/Seoul.
- `itemCode`, `leagueCode`, `homeId`, `awayId`: 실제 응답 필드. `gmTs`/`matchSeq`: 판매 회차/번호.
- `winAllot`/`drawAllot`/`loseAllot`: 같은 응답의 전체 벡터. `betNm`/`betTypNm`, `winHandi`: 구간/시장/부호·기준점.
- 서버가 응답을 읽은 시각은 `observedAt`/`availableAt`. **원천 가격 변경시각은 미제공이므로 null**이다.
- 과거 자료: 기존 네 종목 Google Sheets 및 R2 증분 저장 구조 유지. `opening`/`closing`은 파일 열의 이름이며 실제 시점 이력이 아니다.
- `score`에는 핸디 적용 점수/총점 등이 섞여 있다. 원점수라고 가정해 재정산하지 않는다. 과거 파일의 기존 결과 문자열은 후향 모델에서만 사용하고, 전향 원장의 새 결과 수정본은 정산 규칙 확인 전 `verified=false`로 보관해 운영 재학습 라벨로 승인하지 않는다.
- 일반 무/핸디무는 무 선택만 적중. 홈·원정 선택에는 미적중으로 남긴다. `-`를 임의로 취소/무효로 바꾸지 않는다.

## 실제 시간순 모델·선정 정책

- M0: 같은 스냅샷 전체 가격의 역수 합으로 비례 정규화. 0/누락/불완전 벡터면 null.
- M1: `softmax((alpha × log(M0) + 결과별 절편) / temperature)`인 규제된 power calibration이다. 종목·시장·결과 수별 파라미터를 학습하고 전체 확률 합을 1로 유지한다.
- A=2013–2023-12-24 학습 → B=2024-01-08~12-24 temperature 보정 → C=2025-01-08~12-24 분류 경계 계산 → D=2026-01-08 이후 모델 독립 시험으로 나눴다. 결과 확인시각이 없으므로 각 경계 전후 7일을 제외했다. M1 모델 선택에는 D를 사용했다.
- M1은 M0 대비 대응 Log loss를 비교했고, 달력 주 전체를 함께 재표집한 5,000회 bootstrap을 사용했다. 축구 최종배당 단계 3,639경기·12,350개 시장을 합친 포트폴리오에서 M0 0.877374 → M1 0.876098, 개선 0.001277, 95% 구간 0.000344~0.002285였다. 개별 시장군의 개선 구간은 각각 0을 포함하므로 화면은 이를 개별 시장 우월성으로 설명하지 않는다.
- 야구·농구는 개선 구간이 0을 포함했고 배구는 악화해 공개 모델로 채택하지 않았다.
- M2는 종목→리그→팀의 정확 배당 및 0.05 배당구간 효과를 최소 표본과 강한 수축으로 추가했다. 2026 축구 Log loss가 0.876415로 M1보다 나빠 비활성화했다.
- 고정 70%·배당 1.40 규칙은 폐기했다. 새 분류 단위는 **실제 경기당 최고 M1 시장·결과 1개**다. C에서 이 경기별 최고확률 분포의 90·80 분위수를 공동 등급으로 고정했다. 최상위 신뢰 경계는 0.816798, 고신뢰 관찰 경계는 0.724420이며 배당 하한은 없다.
- 최상위 신뢰의 누적 상위 10% 통계는 C 638경기에서 90.60%(주 블록 95% 구간 88.42~92.84%), D 후향 재현 434경기에서 84.56%(80.73~88.48%)였다. 누적 상위 20% 통계는 C 1,276경기에서 83.86%(82.08~85.69%), D 후향 재현 917경기에서 81.24%(78.52~83.83%)였다. 실제 카드에서는 상위 10%를 `최상위 신뢰`, 두 경계 사이의 10~20% 구간을 `고신뢰 관찰`로 서로 겹치지 않게 표시한다.
- 등급 통과 조건에는 최소 100경기·26주, 주 블록 구간 반폭 5%p 이하, 최상위/고신뢰 적중률 하한 80%/75%, 모델확률 대비 과대추정의 95% 하한 -5%p 이상, 전체 경기 대비 적중률 향상 구간 하한 0 초과가 포함된다.
- 분류법은 기존 D 결과를 확인한 뒤 설계했다. 경계는 C에서만 계산하고 D가 등급을 선택·제거·변경하지 못하게 구현했지만, D 수치는 **후향 재현**으로만 공개한다. 기준을 지금 동결하고 이후 새 E 표본에서 그대로 시험하기 전까지 정책 독립 검증 완료라고 부르지 않는다.
- `p_model > p_market`를 선정 조건으로 쓰지 않는다. 사용자가 확률·배당 경계를 바꿔 검증된 것처럼 보이게 하는 UI와 API 입력도 제거했다.
- 재현 구간의 평균 국내 배당은 최상위 1.070, 고신뢰 1.133이다. 따라서 이 등급은 적중 가능성 순위이며 수익·기대값 우위를 뜻하지 않는다.
- 모델·보정·정책은 데이터, split, 설정, 가중치, 임계값의 내용 해시로 버전 식별한다. CLI 결과가 자동 배포 승인으로 바뀌지 않는다.

## 남은 제한

1. 과거 자료로 경기일시 기준 시간순 검증은 완료했지만, 배당 관측시각과 결과 최초확인시각이 없어 시작 60분 전 같은 고정 시점 성능은 검증할 수 없다. 현재 판매 배당의 M1 값에는 ‘과거 최종배당 단계 대리값’ 안내를 붙인다.
2. 공식 시장별 정산 문서와 결과 소스 대응을 아직 검증하지 못했다. 규칙 레지스트리는 비어 있고 결과 수정본은 verified=false로 보관한다. 과거 결과 문자열 기반 고신뢰 분류는 연구 표시로만 허용하며 화면에 정산 규칙 미확인·후향 재현 사유를 함께 남긴다.
3. 새 고신뢰 분류는 D를 이미 본 뒤 설계했다. 2026 재현 수치가 좋아도 독립 검증 완료가 아니며, 이후 새 표본을 미리 고정한 규칙으로 평가하기 전에는 연구 등급을 유지한다.
4. 예전 변환에서 손실된 점수0·결측 기준점은 추정 복구하지 않았다. 이후 수집부터 올바르게 보존한다.
5. 원천의 안정적인 경기 키/일정 변경 의미가 확정되지 않아 시간·팀 변경을 임의 병합하지 않는다. 이전 source mapping과 스냅샷은 보존하고 의심 항목은 예측에서 제외한다.
6. 수집은 공개 HTTP 조회와 중앙 30초 lease/cache에 의존한다. 이 주기를 원천의 공식 허용 보증으로 부르지 않는다. 소스 장애 시 마지막 관측/오류를 유지한다. 사용자 없는 시간의 기존 스케줄 설정을 새로 보장하거나 무제한 실시간 수집으로 표시하지 않는다.
7. 클라우드 성공 여부는 배포 도구에서 확인한다. 컴퓨터를 끈 뒤에도 기존 클라우드 주소에서 접속·재수집하는 구조를 유지한다.
